Choosing a paradigm

The question is not which paradigm is best, but which one matches the structure of the problem.

Methodology

How the project went from a problem statement to comparable numbers.

1Model the problemState inputs, outputs and the correctness criterion.
2Derive the boundRecurrence, recursion tree or substitution gives Θ, O and Ω.
3Implement variantsNaive and optimized versions that must return identical answers.
4Generate inputsRandom inputs at doubling sizes; a fixed shape per suite.
5MeasureTime, node counts, solution quality and peak memory, best of repeated runs.
6Verify and fitCross-check outputs, then fit c·f(n) and report R² and the empirical exponent.

Benchmark protocol

  • Every optimized algorithm is asserted equal to a reference (sorted(), DP optimum, Bellman-Ford) before timing.
  • Use the best of repeated runs to reduce scheduler and garbage-collection noise.
  • Count nodes or operations where time is too noisy; counts are deterministic.
  • Change one variable at a time: algorithm, then input size.
  • Judge scaling by the fitted exponent and R², not by a single timing.

Complexity classes

Polynomial-time reduction map (A → B: B is at least as hard as A):

SAT→3-SAT→Clique→Vertex Cover→Hamiltonian Cycle→TSP
3-SAT→Subset Sum→Partition→0/1 Knapsack (pseudo-polynomial DP exists because W is numeric, not a size bound)
PSolvable in polynomial time: MST, shortest paths, max-flow.
NP / NP-completeVerifiable in polynomial time: SAT, Subset Sum, TSP (decision). Polynomial reductions link them.
NP-hardAt least as hard as NP-complete: tackled with exact search (B&B), approximation (2-approx vertex cover) and heuristics.

Test environment & limits

Detected from the device viewing this page, so the numbers above can be interpreted honestly.

The numbers CAN sayRelative scaling shape, crossover points, the effect of pruning and memoization (node counts are deterministic), and whether each variant returns identical answers.
The numbers CANNOT sayAbsolute production speeds (one machine, JavaScript and Python, timer noise), cache and branch-prediction effects, adversarial worst cases, parallel or distributed behaviour, or behaviour beyond the tested sizes.
